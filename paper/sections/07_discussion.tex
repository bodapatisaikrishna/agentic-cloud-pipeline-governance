\section{DISCUSSION}\label{sec:discussion}

\subsection{Implications for Evaluating Governed Agents}
The mock-versus-live divergence (Section~\ref{sec:livemock}) bears directly on how systems of this
kind should be evaluated, and four practices follow from the results and from the lessons of
Section~\ref{sec:lessons}. First, state whether the model in the loop was real or mocked, and report
both numbers whenever both exist, because a mock figure describes only the mock. Second, include cheap
non-LLM baselines: here two idealized baselines beat the full agent system on recovery time and
manual interventions, which a comparison against static orchestration alone would have concealed.
Third, grade any safety claim against an oracle that shares no code with the mechanism under test; the
independent oracle used here found two contract-layer gaps that the system's own tests had missed.
Fourth, run a short, paid pilot at the real settings before committing to a long campaign; ours
detected a retired model on its first call.

\subsection{Deployment Implications}
For deployment, the most relevant decision-quality figure is $\NDeltaDecisionCorrectFull{}$, not the
headline MTTR: at these settings \texttt{full} executes an accepted mitigation in fewer than half of
its runs. Together with the rise in manual interventions, this campaign gives no support for running
this class of system unattended and fully autonomously against real infrastructure. The results
instead favor the graduated trust ladder of Section~\ref{sec:system} as the safer production
default: shadow, approval, and autonomous modes, with a durable kill switch and a per-target action
cap. They also argue against treating the research benchmark's default of full autonomy as a
deployment recommendation. For now, the trust core is an architectural response to a question that
our measurements raise; we have not yet measured whether it works.

\subsection{The Manual-Intervention Mechanism Is Measured, Not Explained}
Section~\ref{sec:results} reports that \texttt{full} and \texttt{recovery\_only} increase manual
interventions relative to \texttt{baseline}, contrary to the base paper's claim. The measurement
itself is direct: the metric counts rows in the
\texttt{telemetry.\allowbreak manual\_\allowbreak interventions} table, to which every configuration
writes. The mechanism behind the increase is not established. Repeated escalation across the ticks of
one open fault may dominate, repeated denials may end in human hand-offs, or the two may interact.
Distinguishing these explanations would require a per-tick trace of proposal outcomes over the
lifetime of a fault, which the current telemetry does not retain. We therefore leave the mechanism
open rather than infer it from the aggregate count, and readers should not regard it as resolved in
the system's favor.

\subsection{Limitations and Threats to Validity}\label{sec:limitations}

\subsubsection{Threats to Validity}
Eight threats apply directly. \emph{Simulated human.} Every comparison against \texttt{baseline}
inherits the log-normal on-call model; Section~\ref{sec:sensitivity} reports the break-even point
rather than defending the model itself. \emph{Modelled baselines.} \texttt{rule\_based} and
\texttt{autoscale} resolve covered faults after fixed, assumed latencies (Section~\ref{sec:method}),
so their advantage over the agents reflects those assumptions and is not a measurement of a deployed
rule engine or autoscaler. \emph{Synthetic workload.} The data come from a downscaled synthetic table
with injected faults rather than from production traces, and the results may not carry over to real
workloads. \emph{One live model family.} The live arm used one reasoning model and one faster model
from a single provider at temperature zero, so the decision-quality findings
(Section~\ref{sec:results}) are properties of that pairing and may not generalize. \emph{Unequal
replicate counts.} \texttt{baseline}, \texttt{rule\_based}, \texttt{autoscale}, and \texttt{full} each
have $\NNFull{}$ runs, whereas the four single-agent ablations have half as many. This cost trade-off
was made before the campaign (Section~\ref{sec:method}) and widens the ablations' confidence
intervals relative to the headline comparisons. \emph{Nominal seed matching.} Because the per-run
seed depends on the configuration name (Section~\ref{sec:method}), no two configurations share fault
or human-latency randomness at a matched (scenario, replicate) index. We therefore used the unpaired
rank-sum test as the primary test, and the retained signed-rank statistic should not be read as
evidence from a paired design. \emph{Detection-clock asymmetry.} Non-agent configurations detect at
injection by construction, whereas agent configurations start the MTTR clock only when the monitoring
agent flags the fault (Section~\ref{sec:problem}). The agents' recovery times therefore omit a
detection interval that the non-agent figures include, which favors the agents in every MTTR
comparison. \emph{Cost measurement.} The metered term of Eq.~\eqref{eq:cost} is integrated between two
resource samples per run, which spans the 300\,s control loop for agent configurations but only a few
seconds for non-agent ones. In addition, the Airflow pool size and the streaming-worker target carry
over from one run to the next because the campaign never reset them. Cost comparisons therefore rest
mainly on the provisioning term, an assumption whose break-even point Section~\ref{sec:sensitivity}
reports, and the metered part should not be read as a like-for-like measurement.

\subsubsection{Scope of the Testbed}
The testbed is a single machine. The resource-contention scenario applies real CPU stress, which is
why runs cannot be parallelized and why the size of the campaign is bounded. The policy engine is
pinned to one release, and lesson L6 (Section~\ref{sec:lessons}) shows that a newer release from the
same vendor would have changed the adversarial result had the version not been pinned. We disclose
this as a property of our evaluation, not as a defect we investigated in the policy engine. Only four
fault types were injected, whereas a real pipeline's incident taxonomy is larger, and lesson L4
(Section~\ref{sec:lessons}) shows that mapping an injected fault type onto a real incident type is not
automatic.

\subsubsection{Evidence Gaps}
Two components described in Section~\ref{sec:system} are implemented but not evaluated, and a third
gap lies within a contribution that is otherwise evaluated. \emph{Cross-model generalization.} The
harness that could test the base paper's claim of model independence is unit-tested, but its live
sweep against real provider models has not been run, so nothing here is evidence for or against that
claim. \emph{The trust core.} Graduated autonomy, the kill switch, and the blast-radius cap are
implemented and unit-tested, but every configuration ran in one fixed mode, so no mode transition or
kill-switch-to-halt latency was measured. \emph{Cost.} The cost model computes a compute and storage
split internally, but the committed per-run data keep only the combined total, and the metered term
is confounded as described above.

Each gap has a concrete and bounded remedy. The cross-model sweep should be run against at least two
live providers on the same scenario set. A dedicated drill should engage the kill switch and a mode
transition under load and record the timing. For cost, the harness should reset the pool size and the
worker target before each run, sample resources at a fixed cadence over a window that is identical
for every configuration, and persist the ledger's component breakdown. The first two gaps are
evidence this campaign did not collect; the third is a measurement flaw that a re-run with these
changes would remove.

\subsubsection{What Would Change Our Conclusion}
A cross-model repetition of Section~\ref{sec:livemock} that reproduced the same order-of-magnitude
mock-versus-live gap with a different provider would considerably strengthen the central claim. A
repetition that did not would suggest that the gap is specific to this model pairing rather than a
property of mock evaluation as a method, and that result would deserve an equally plain report.
