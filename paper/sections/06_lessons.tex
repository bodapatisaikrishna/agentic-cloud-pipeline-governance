\section{PRODUCTION-HARDENING LESSONS}\label{sec:lessons}

The central finding of Section~\ref{sec:livemock} has a less statistical counterpart. The system had
several defects that its own test suite could not see, for the same reason that the mock evaluation
flatters the headline numbers: the path the tests exercised was not the path production takes. Each
lesson below was found through an audit or an experiment rather than through a failing test, and each
is documented in the accompanying artifact.

\subsection{L1: The Shared Resource Nobody Declared Concurrency-Unsafe}\label{sec:l1}
Although the base design describes execution as deterministic and auditable, our code for creating a
versioned partition read the current maximum version and then dropped, created and registered a
table in separate statements with no lock held, so that two callers working on the same partition at
once could arrive at the same next version. The symptom was an intermittent failure in continuous
integration. Rather than rerun the job until it passed, we traced it and found that a replay issued by
the recovery agent had triggered a DAG that an unrelated test was using at the same moment. The
read-modify-write is now protected by a database advisory lock. \emph{Lesson:} once an agent is
allowed to start real work, any resource it shares with other actors needs concurrency control, and a
single-actor test suite will not reveal the problem.

\subsection{L2: An Action Could Be Lost From the Audit Trail}\label{sec:l2}
In the first version the audit row was written \emph{after} execution. A crash in that window,
whether an out-of-memory kill or a lost database connection, could therefore let an action take
effect without any record of it, and because the control loop catches per-tick exceptions the loss
would probably have gone unnoticed. Since the system's central promise is that every action is both
gated and audited, a single unaudited action would be enough to break it. The intent row, which
already contains the policy verdict, is now committed \emph{before} execution and completed with the
outcome afterwards. \emph{Lesson:} the record of what an agent intends to do should be durable before
the agent does it.

\subsection{L3: The Detector That Had No Callers}\label{sec:l3}
Only the fault injector wrote to the table that both the recovery-time statistics and decision
scoring read from. The monitoring agent updated the detection time on a row that already existed but
never inserted one. The result was a complete, deterministic anomaly detector, with unit tests, that
nothing called. Without the injector, a real incident that the agent detected would have reached the
audit table but never become an incident record, and production would have been unable to reproduce
the experiment's own metrics. We noticed this while planning a later feature, by reading the code; no
test failed. \emph{Lesson:} a component can pass all of its own tests and still be disconnected, so
follow the data from production input all the way to the reported metric.

\subsection{L4: Two Taxonomies That Never Met}\label{sec:l4}
Decision correctness is scored against a set of accepted mitigations (Eq.~\eqref{eq:decision}), and
that set is keyed by the name of the \emph{injected scenario}. Live incidents use different fault-type
names.
Applying the set to live incidents would have marked every real incident ``incorrect by
construction.'' A mapping from live fault types onto the same accepted-mitigation set was added
before the metric was exposed outside the experiment harness. \emph{Lesson:} a metric defined in the
experiment's own vocabulary cannot move into production without an explicit mapping.

\subsection{L5: Hermeticity by Enumeration Does Not Scale}\label{sec:l5}
One class of unit-test failure kept recurring: a test that did not mock one module's database handle
turned a millisecond test into a thirty-second connection-pool timeout. We patched it one test at a
time, four times over, before dealing with the cause. All such calls
now go through a single connection-pool accessor, which the test setup patches to fail at once. When
we removed one essential mock to check the guard, six tests failed within seconds and each one named
the cause. \emph{Lesson:} a bug that has been fixed four times in four places is a sign that the
mechanism producing it needs to change.

\subsection{L6: What the Adversarial Corpus Found}\label{sec:l6}
When the generated corpus was graded against the independent oracle (the numbers are in
Section~\ref{sec:results}), three findings emerged. The first was a pair of gaps in the contract
layer. Because the cost policy compared a scaling target with the budget without checking a lower
bound, a target of zero workers, which stops ingestion altogether, passed as within budget, and a
negative ``scale-down'' passed as well. Separately, a non-numeric target made the gate raise an
exception before the audit row had been written, so a proposal that was in effect rejected could leave
no trace. Both gaps have been closed in the contract layer, which now requires scaling targets to be
integers no smaller than one and sends any violation down the normal invalid-output path.

The second finding concerned the policy engine itself. Run under a newer release than the one pinned
for this project (Table~\ref{tab:testbed}), some floating-point budget comparisons came out as within
budget when they were not, while the pinned release handled them correctly. We have neither traced
the root cause nor reported it upstream. Whatever the cause turns out to be, the pin is needed, and the
corpus now also serves as an integration test that should catch any later upgrade that alters these
semantics.

Third, once the contract fixes were in, the policy agreed with the independent specification on all
graded cases, so containment is now a measured quantity with a confidence interval rather than an
assertion inherited from the code under test. \emph{Lesson:} a policy that its authors consider safe
should be regarded as untested until an oracle written independently of it has tried to break it and
failed.

\subsection{L7: The Pilot Found a Retired Model}\label{sec:l7}
Before the live campaign, an eight-run pilot at the real paper timings measured cost and wall time.
Within minutes it found that the provider had retired the small model configured for the monitoring
agent (HTTP 410, end of life). Because monitoring is the detector in every agent configuration, the
full campaign would otherwise have run with a detector degraded to a no-op, and every downstream
number would have measured the provider's retirement of the model rather than the system. The
supervisor has a guard against streaks of degraded calls, so it would have caught the problem
eventually, but only after several runs had been wasted. The pilot caught it on the first call.
\emph{Lesson:} in a long experiment that costs money, the cheapest validity check is a short run with
the real settings. A model that a provider still lists may no longer answer.

\subsection{L8: The Simulated Engineer Rewarded Repeated Escalation}\label{sec:humanartifact}
After the campaign we found a flaw in the on-call model that favours any configuration escalating
more than once. The simulator gave each escalation row its own log-normal delay and closed the fault
when the fastest one finished. An agent that escalated on several ticks of the same fault thus drew
several delays and kept the shortest.

agents, and that some of the increase in manual interventions has the same origin, since each
re-escalation was recorded as a further row.

The simulator now pages the engineer once per incident, starting at the first escalation, with a
single delay per fault that paired runs share (D-106 in the repository). A pre-registered
re-run with the corrected simulator is planned, but none of its numbers appear here. \emph{Lesson:}
because a simulated human is part of the measuring instrument, it has to be checked as carefully as
the system under test, and in particular its output should not depend on how often the system asks
it for help.
