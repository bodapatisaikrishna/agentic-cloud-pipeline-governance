\section{PRODUCTION-HARDENING LESSONS}\label{sec:lessons}

The central finding of Section~\ref{sec:livemock} has a less statistical counterpart. The system had
several defects that its own test suite could not see, for the same reason that the mock evaluation
flatters the headline numbers: the path the tests exercised was not the path production takes. Each
lesson below was found through an audit or an experiment rather than through a failing test, and each
is documented in the accompanying artifact.

\subsection{L1: The Shared Resource Nobody Declared Concurrency-Unsafe}
The base design states that execution is deterministic and auditable. Versioned partition creation,
however, read the current maximum version and then dropped, created, and registered a table in
separate statements without a lock, so two concurrent callers targeting the same partition could
compute the same next version and race. It first showed up as a continuous-integration failure that
came and went. We tracked it down instead of retrying until it passed, and found that a replay by the
recovery agent had triggered the same DAG that an unrelated test was using. The fix wraps the
read-modify-write in a database advisory lock. \emph{Lesson:} as soon as an agent can start real
work, every shared resource it touches becomes a concurrency problem, and a test with a single actor
will never exercise it.

\subsection{L2: An Action Could Be Lost From the Audit Trail}
At first the audit row was written \emph{after} execution. If the process crashed, was killed for
running out of memory, or lost its database in that window, an action could take effect and leave no
record behind. The control loop swallows per-tick exceptions, so nobody would have noticed. The
system's main promise is that every action passes the policy gate and is audited, and an action with
no audit row breaks that promise outright. Now the intent row, which already holds the policy verdict,
is committed \emph{before} execution and updated with the outcome once the action finishes.
\emph{Lesson:} write down the intent first and act second.

\subsection{L3: The Detector That Had No Callers}
Only the fault injector wrote to the table that both the recovery-time statistics and decision
scoring read from. The monitoring agent updated the detection time on a row that already existed but
never inserted one. The result was a complete, deterministic anomaly detector, with unit tests, that
nothing called. Without the injector, a real incident that the agent detected would have reached the
audit table but never become an incident record, and production would have been unable to reproduce
the experiment's own metrics. We noticed this while planning a later feature, by reading the code; no
test failed. \emph{Lesson:} a component can pass all of its own tests and still be disconnected, so
follow the data from production input all the way to the reported metric.

\subsection{L4: Two Taxonomies That Never Met}
Decision correctness is scored against a set of accepted mitigations (Eq.~\ref{eq:decision}), and
that set is keyed by the name of the \emph{injected scenario}. Live incidents use different fault-type
names.
Applying the set to live incidents would have marked every real incident ``incorrect by
construction.'' A mapping from live fault types onto the same accepted-mitigation set was added
before the metric was exposed outside the experiment harness. \emph{Lesson:} a metric defined in the
experiment's own vocabulary cannot move into production without an explicit mapping.

\subsection{L5: Hermeticity by Enumeration Does Not Scale}
One class of unit-test failure kept recurring: a test that did not mock one module's database handle
turned a millisecond test into a thirty-second connection-pool timeout. We patched it one test at a
time, four times over, before dealing with the cause. Now every such call goes through one
connection-pool accessor, and under test that accessor is patched to fail immediately. Mutation
testing of this guard, by removing one essential mock, made six tests fail within seconds, each naming
the exact cause. \emph{Lesson:} by the fourth time the same bug turns up, stop fixing instances and
fix the mechanism.

\subsection{L6: What the Adversarial Corpus Found}
Grading a generated corpus against an independent oracle revealed three things (numbers in
Section~\ref{sec:results}). First, the contract layer had two gaps. The cost policy priced a scaling
target against the budget but did not check its floor. Zero workers, which halts ingestion entirely,
was therefore within budget, and so was a negative ``scale-down.'' In addition, non-numeric targets
raised an exception inside the gate before the audit row was written, so a rejected proposal could
leave no record. Both gaps are now closed in the contract layer: scaling targets must be integers of
at least one, and any violation follows the ordinary invalid-output path.

Second, under a newer policy-engine release than the one this project pins, some floating-point budget
comparisons evaluated as within budget when they were not, whereas the pinned release behaved
correctly. We have not traced the root cause or filed an upstream report. Whatever the cause, the
practical consequence is the same: the version pin is necessary, and the corpus now doubles as an
integration test that would flag any future upgrade that changes these semantics.

Third, with the contract fixes in place, the policy matched the independent specification on every
graded case. Containment is now something we measured, with a confidence interval, and not a claim
copied from the code under test. \emph{Lesson:} when a policy's own authors say it is safe, treat
that as a hypothesis until an independent oracle has tried and failed to break it.

\subsection{L7: The Pilot Found a Retired Model}
Before the live campaign, an eight-run pilot at the real paper timings measured cost and wall time.
Within minutes it found that the provider had retired the small model configured for the monitoring
agent (HTTP 410, end of life). Because monitoring is the detector in every agent configuration, the
full campaign would otherwise have run with a detector degraded to a no-op, and every downstream
number would have measured the provider's retirement of the model rather than the system. The
supervisor has a guard against streaks of degraded calls, so it would have caught the problem
eventually, but only after several runs had been wasted. The pilot caught it on the first call.
\emph{Lesson:} in a long experiment that costs money, the cheapest validity check is a short run with
the real settings. A model that a provider still lists may no longer answer.
